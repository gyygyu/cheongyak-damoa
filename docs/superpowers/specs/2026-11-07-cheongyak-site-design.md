# 청약다모아(가칭) 설계 문서

- 작성일: 2026-11-07
- 상태: 사용자 검토 대기
- 저장소: `파이썬/청약사이트` (새 저장소, 지원금다모아와 별개)

## 1. 목표와 범위

아파트 청약·공모주 일정과 실거래가를 한곳에서 보여 주는 조회 사이트다. 검색으로 들어온 방문자에게 광고를 붙여 수익을 낸다. 운영비는 월 0원에서 시작한다.

- **지금(11-17 전):** 화면·구조·동기화를 만들고, 내 PC에서 실제 API로 돌려 본다(로컬 D1·KV).
- **11-17 이후:** Cloudflare 가입·도메인 구입·배포만 남긴다. 순서는 `docs/deploy.md`에 미리 적어 둔다.

### 첫 공개 기능

1. 청약 캘린더와 단지 상세
2. 공모주 일정과 종목 상세
3. 특별공급 자격 판정(브라우저 안에서만)
4. 경쟁률 모음
5. 실거래가: 단지 주변 시세 비교, 지역별(동별) 실거래, 분양권 실거래

### 범위 밖(보류)

- 지도, 알림(메일·푸시), 회원 기능, 청년 특공(제35조의2)
- 일반공급 가점 계산기: 1차 범위가 아니다. 공개 뒤 방문 데이터를 보고 정한다.
- 오피스텔·도시형 생활주택·무순위(줍줍): 출처 API 범위를 확인한 뒤 2차에서 정한다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 저장소 | 새 저장소. 지원금다모아에서 검증된 코드만 복사한다. 지원금다모아 쪽은 건드리지 않는다. |
| 스택 | Astro SSR + `@astrojs/cloudflare`(Workers), D1, KV, GitHub Actions 동기화, TypeScript, vitest. 버전은 지원금다모아와 같게 맞춘다. |
| 도메인 | 한 도메인에 탭을 두는 방식을 권한다(청약다모아, 예: cheongyakdamoa.com). **아직 확정하지 않았다.** 이름은 `src/lib/site-meta.ts` 한 곳에서만 바꾸도록 만든다. |
| Cloudflare 계정 | 무료 한도를 나눠 쓰지 않도록 **별도 계정**으로 한다. 가입은 사용자가 나중에 한다. 약관에 걸리는 내용이 있으면 같은 계정에 두고 Workers Paid(월 5달러)로 바꾼다. 어느 쪽이든 코드는 같고, `.env`의 토큰만 달라진다. |
| 신뢰 장치 | 지원금다모아의 trust/code-guard는 넣지 않는다. Actions는 `main` 브랜치에서만 돈다. 이 저장소에 AI 자동 게시 기능이 없기 때문이다. |

## 4. 아키텍처

```
GitHub Actions (예약 실행)
  └─ sync/ (Node 전용)
       수집(출처별) → 변환(순수 함수, src/lib) → 해시 비교 → 바뀐 행만 D1 SQL
                                                → 화면용 묶음을 미리 계산해 KV에 올림
Cloudflare Worker (Astro SSR)
  └─ 페이지마다 KV 묶음 1개를 읽어 렌더링 (큰 JSON 파싱 금지)
브라우저
  └─ 자격 판정: 입력값은 브라우저 밖으로 보내지 않는다 (URL 쿼리 포함)
```

### 디렉터리

- `src/lib/`: 순수 로직. Cloudflare·Node API를 쓰지 않으며, 브라우저·Worker·Node에서 함께 쓴다. 테스트는 `tests/`에 둔다.
  - `apt/`: 공고 변환, 일정 정리, 상태(정상·정정·취소·종료)
  - `ipo/`: DART 신고서 판 고르기, 일정·가격 정리
  - `trade/`: 금액 변환, 해제 제외, 중위가, 주변 시세 묶음, 분양권 매칭
  - `region/`: 주소 → `LAWD_CD`·법정동 해석
  - `eligibility/`: 특공 판정(§8), 소득 기준표 조회
  - `units.ts`: ㎡↔평 변환과 표기
  - `site-meta.ts`: 사이트 이름·주소
- `src/server/`: `DB`·`KV` 바인딩을 쓰는 코드
- `src/pages/`: 페이지
- `sync/`: Node 전용 동기화. 출처별로 따로 비교·기록한다(`SOURCES`).
- `sync/fixtures/`: 출처별 실응답 샘플. 키 없이 `npm test`와 로컬 동기화가 돌게 한다.
- `migrations/`: D1 스키마
- `content/`: 법정동코드 표, 소득 기준표
- `docs/`: `deploy.md`(11-17 이후 순서), `api-fields.md`(실응답 필드 조사), `traffic-log.md`

### 지원금다모아에서 옮겨 올 것

다음 파일을 복사해 새 저장소에 맞게 고친다. 원본은 고치지 않는다.

- `sync/sql.ts`, `sync/cloudflare.ts`, `sync/artifacts.ts`: 해시 변경분 → SQL 파일, KV 업로드
- `src/lib/html.ts`, `paging.ts`, `canonical-host.ts`, `cache-key.ts`, `kv-keys.ts`: 공용 유틸
- 전역 CSS: 강조색만 바꾼다.
- `sync/ops-daily.ts`와 `sync/ops/`: 매일 점검. 이 사이트의 Actions 이름과 주소에 맞춘다.
- 사이트맵·IndexNow: 배포 뒤에 켠다.

## 5. 데이터 모델 (D1)

모든 표에 `hash`(원본 정규화 값의 해시)와 `updated_at`을 둔다. 해시가 바뀐 행만 쓴다.

| 표 | 키 | 주요 열 |
|---|---|---|
| `apt_notice` | `pblanc_no` | 주택관리번호, 단지명, 시도·시군구, 주소, `lawd_cd`, 법정동, 공급 구분(국민/민영), 공공택지 여부, 투기과열·조정 여부(출처에 있을 때), 모집공고일, 특공·1순위·2순위 접수일, 당첨자 발표일, 계약 기간, 총 세대수, 청약홈 링크, 상태 |
| `apt_model` | `pblanc_no`+`model_no` | 주택형, 전용면적, 공급면적, 일반·특공 유형별 세대수, 최고 분양가(만원) |
| `apt_competition` | `pblanc_no`+`model_no`+순위+거주구분 | 공급 세대수, 접수 건수, 경쟁률 |
| `apt_special_status` | `pblanc_no`+`model_no`+특공 유형 | 배정 세대수, 신청 건수 |
| `trade` | 거래 해시 | `lawd_cd`, 법정동, 지번, `apt_seq`, 단지명, 전용면적, 층, 계약일, 금액(만원, 정수), 건축년도, 해제 여부·해제일 |
| `presale_trade` | 거래 해시 | `sgg_cd`, 법정동, 지번, 단지명, 전용면적, 층, 계약일, 금액, 구분(분양권/입주권), 해제 여부 |

- 거래 해시: 출처에 고유번호가 없으므로 `lawd_cd`·법정동·지번·단지명·면적·층·계약일·금액을 합쳐 만든다. 같은 날, 같은 층, 같은 금액의 거래가 겹치면 해시 뒤에 순번을 붙인다.
- **D1 쓰기 예산(무료 하루 10만 행):**
  - 평소: 공고·경쟁률은 수백 행, 실거래 재수집 변경분은 수천 행이다.
  - 백필: 하루 예상치가 7만 행을 넘으면 그날 백필을 멈추고 다음 날 이어서 받는다.

## 6. KV 묶음

페이지마다 미리 계산한 작은 JSON 하나를 둔다. 값 하나는 50KB 안쪽이 목표다. Worker가 10ms 안에 파싱할 수 있어야 하기 때문이다. 이보다 크면 쪼개거나 Worker에서 파싱하지 않고 스트림으로 넘긴다.

| 키 | 내용 |
|---|---|
| `home` | 오늘·이번 주 청약과 공모주 타임라인, 최근 경쟁률 상위 |
| `calendar:YYYY-MM` | 그달 일정(청약 접수·발표·계약, 공모주 청약·환불·상장) |
| `apt:{공고번호}` | 공고, 주택형, 경쟁률, 특공 현황, 주변 시세 비교, 분양권 거래 |
| `ipo:{고유번호}` | 일정, 가격, 주관사, 정정 이력, DART 원문 링크 |
| `region:{시도}`, `region:{시도}:{시군구}` | 그 지역 공고·최근 실거래 요약 |
| `trade:{시군구코드}:{법정동}` | 동별 실거래 표(최근 12개월, 단지별) |
| `competition` | 최근 공고 경쟁률 모음 |
| `meta:sources` | 출처별 마지막 성공 시각, 연속 실패 수 |
| `backfill:trade` | 백필 진행 위치 |

## 7. 주소와 화면

탭은 **아파트 청약 · 공모주 · 실거래 · 캘린더 · 자격 판정** 다섯 개다.

| 주소 | 화면 |
|---|---|
| `/` | 홈 타임라인: 오늘·이번 주 일정, 마감 임박, 최근 경쟁률 |
| `/calendar/YYYY-MM` | 월 캘린더. 휴대폰에서는 목록으로 보이고, 청약·공모주를 걸러 볼 수 있다. |
| `/apt/{공고번호}` | 단지 상세: 일정, 주택형별 분양가(㎡당·평당), 경쟁률, 특공 현황, 주변 시세 비교, 분양권 거래, "이 단지로 자격 판정" 버튼 |
| `/ipo/{고유번호}` | 공모주 상세: 일정, 희망가·확정가, 주관사, 정정 이력 |
| `/region/{시도}[/{시군구}]` | 지역별 공고와 실거래 요약 |
| `/trade/{시군구}/{법정동}` | 동별 실거래 표: 단지별, 면적대별, 최근 거래 |
| `/competition` | 경쟁률 모음 |
| `/eligibility` | 특공 자격 판정 |

- **보기:** 휴대폰 우선. 지원금다모아 CSS에서 강조색만 바꾼다. 숫자는 `tabular-nums`로 쓰고, 면적은 "84㎡(25평)"처럼 함께 적는다.
- **종료된 공고:** 404 대신 "접수가 끝난 공고입니다" 화면과 결과(경쟁률)를 보여 준다.
- **정정·취소 공고:** 배지로 표시한다.
- **광고:** 애드센스 승인 전에는 자리만 두고 비워 둔다.

## 8. 특별공급 자격 판정

### 근거

「주택공급에 관한 규칙」(시행 2026. 6. 15., 국토교통부령 제1592호). 출처: 법제처 국가법령정보센터. 구현할 때 조문 원문을 다시 확인하고, 테스트 이름에 조·항을 적는다.

### 유형별 요건

| 유형 | 조문 | 판정하는 요건 |
|---|---|---|
| 신혼부부 | 제41조 ①(민영 85㎡ 이하)·④(국민) | 혼인 7년 이내, 무주택세대구성원, 소득 140%(맞벌이 160%) 이하. 넘으면 부동산 가액 기준(건보 재산등급 29등급 하한·상한 평균)으로 가므로 "확인 필요". 혼인 중 자녀가 있으면 1순위. 배정은 ③·⑥에 따라 50%(100%·120%), 20%(140%·160%), 나머지는 추첨 |

### 공통 요건

- 제48조: 통장 가입 6개월 이상. 국민은 6회 이상 납입, 민영은 지역·면적별 예치금.
- 제55조: 특공은 한 번만 받을 수 있다.
- 제55조의3 ③: 2024. 6. 19. 이후 출생한 자녀가 있으면 한 번 더 신청할 수 있다.
- 제49조의2: 기관추천. 기관추천·비수도권·지역균형·철거주택(제39조·제42조·제44조)은 안내만 한다.

### 판정 방식

- 브라우저에서만 계산하고, 결과는 **가능 / 불가 / 확인 필요** 세 가지로 낸다. 결과마다 걸린 요건과 조문을 함께 보여 준다.
- 1순위 여부(지역·통장 순위)와 부동산 가액은 사용자가 정확히 알기 어려우므로 "확인 필요"로 둔다.
- 소득 기준표는 `content/income-table/{연도}.json`에서 연도별로 읽는다. 공고일이 속한 해의 표가 없으면 소득 요건은 "확인 필요"로 둔다.
- 단지 상세에서 들어오면 국민/민영, 면적, 공고일을 미리 채운다. 이 값은 공개 데이터이므로 URL 경로로 넘겨도 된다. 사용자가 입력한 값은 URL로 넘기지 않는다.

## 9. 데이터 연결

- **단지 주소 → 지역:** 공고 주소를 법정동코드 표로 해석해 `LAWD_CD`(시군구 5자리)와 법정동을 얻는다. 해석이 안 되면 주변 시세를 "비교 자료 없음"으로 둔다.
- **주변 시세(sync 때 미리 계산):**
  - 대상: 같은 법정동, 최근 12개월, 준공 10년 이내, 해제 거래 제외, 주택형 전용면적 ±10㎡
  - 값: ㎡당 중위가. 이를 평당가로 바꾸고, 주택형 분양가와 나란히 보여 준다.
  - 5건 미만이면 시군구로 넓힌다. 그래도 5건 미만이면 "비교 자료 부족(n건)"으로 표시한다.
  - 문구는 사실만 쓴다(예: "주변 같은 면적대 ㎡당 중위가 ○○만원, 이 단지 분양가 ○○만원"). "싸다·비싸다·차익" 같은 평가는 쓰지 않는다.
- **분양권 매칭:** `sggCd` + 법정동 + 지번으로 맞춘다. 실패하면 단지명을 정규화해(공백·괄호·"아파트"·차수 표기 정리) 다시 맞춘다. 그래도 실패하면 동별 표에만 넣는다. 매칭 방법은 `presale_link`에 남긴다.
- **공모주 판 고르기:** DART 증권신고서 중 접수번호가 가장 늦은 판을 쓴다. "[기재정정]"이면 앞 판을 덮어쓰고 정정 이력에 남긴다. 확정 공모가·청약 경쟁률·상장일이 어느 공시(투자설명서·발행조건확정·증권발행실적보고서)에 있는지는 첫 작업에서 실키로 확인해 `docs/api-fields.md`에 적는다.

## 10. 오류 처리와 한도

- **출처별 분리:** 한 출처가 실패해도 다른 출처는 반영한다. 실패한 출처는 직전 KV를 그대로 두고, 화면에 "마지막 갱신 시각"을 보여 준다.
- **이상치 차단:** 받은 건수가 0이거나 직전보다 70% 넘게 줄면 그 출처는 반영하지 않는다.
- **연속 실패:** 같은 출처가 3회 연속 실패하면 GitHub 이슈를 연다.
- **금액·거래:**
  - `dealAmount`는 쉼표·공백을 지우고 만원 단위 정수로 바꾼다.
  - 해제 거래는 표에 "해제" 표시와 함께 보여 주되, 통계(중위가)에서는 뺀다.
- **Workers:** CPU는 요청당 10ms다. 페이지는 KV 묶음 하나만 읽고, 큰 JSON은 파싱하지 않는다.
- **KV 쓰기(무료 하루 1,000건):** 바뀐 묶음만 올린다. 하루 예상 쓰기가 800건을 넘으면 동별 실거래 묶음은 다음 실행으로 미룬다.

## 11. 테스트

TDD로 만든다. 키 없이 `npm test`가 통과해야 한다.

- **조문 경계값:** 혼인 7년째 마지막 날, 자녀 2세 생일 전날, 소득 140%·160% 경계, 60㎡·85㎡ 경계, 노부모 부양 3년 경계, 2024. 6. 19. 출생 경계
- **주소 해석:** 도로명·지번 주소, 세종·제주처럼 시군구가 없는 곳, 행정구 있는 시(예: 수원시 영통구)
- **중위가:** 짝수·홀수 건수, 해제 제외, 5건 미만일 때 넓히기
- **지번 매칭:** "산" 지번, 부번 없음, 단지명 정규화
- **정정 판 선택:** 접수번호 순서, "[기재정정]" 덮어쓰기, 정정 이력
- **이상치 차단:** 0건, 70% 감소
- **회귀:** `sync/fixtures/`의 실응답 샘플로 수집 → 변환 → SQL·KV 산출물을 비교한다.

## 12. 운영

- `npm run ops:daily`: 지원금다모아 것을 옮겨 온다. 어제 방문, Worker·D1·KV 한도, Actions 결과, 실서버 응답을 읽기만 한다. 배포 뒤에 켠다.
- **11-17 이후 사용자 몫:**
  1. Cloudflare 가입(별도 계정)
  2. 도메인 구입
  3. GitHub 저장소 생성과 Secrets 등록(`DATA_GO_KR_KEY`, `DART_API_KEY`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`)
  4. 서치콘솔·네이버 서치어드바이저 등록
  5. 애드센스 신청

  자세한 순서는 `docs/deploy.md`에 둔다.
- 비밀값은 `.env`(로컬)와 GitHub Secrets에만 둔다.
